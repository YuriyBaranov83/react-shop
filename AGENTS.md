# AGENTS.md

## Главные правила

- Перед любой задачей сначала прочитать этот файл.
- Работать только в рамках поставленной задачи.
- Не делать лишний рефакторинг по своей инициативе.
- Не менять несвязанные файлы.
- Не переписывать рабочий код, если задача этого не требует.
- Если найден unrelated bug — сообщить отдельно, но не исправлять без разрешения.
- Держать изменения маленькими и понятными.

## Контент и локализация

- Не добавлять статичный текст на русском языке в пользовательский интерфейс.
- Это касается JSX, data-файлов, `alt`, `title`, `aria-label`, `placeholder`, meta-текстов и любых других строк, видимых пользователю.
- Не добавлять в проект российский контекст: адреса, города, телефоны, домены, валюту `RUB`, символ `₽`, обозначения `руб.`, российские организации и любые другие привязки к РФ.
- Если нужен новый статичный текст и язык не указан, использовать украинский.
- Если найден существующий русский текст или российский контекст вне текущей задачи — сообщить отдельно, но не исправлять без разрешения.

## CSS и классы

- В проекте используются CSS Modules.
- Не переименовывать CSS-классы без необходимости.
- Не переводить существующие классы из kebab-case в camelCase.
- Если в CSS есть класс `.section-title`, использовать его так:

  ```jsx
  className={styles["section-title"]}
  ```

- Не менять его на:

  ```jsx
  className={styles.sectionTitle}
  ```

- Если класс нужно переименовать, менять одновременно и JSX, и CSS.
- Не переносить локальные стили в globals.css.
- Не писать inline styles без необходимости.
- Использовать существующие CSS variables/tokens, если они уже есть в проекте.

- Размеры текста и связанные отступы задавать в `rem`; сохранять `html { font-size: 100%; }`, чтобы учитывать настройки браузера.
- Для тонких границ, обводок, теней и медиазапросов допустимы `px`. Не переводить единицы механически без проверки адаптивности.
- Повторяющиеся цвета, интервалы, радиусы и типографику брать из `src/styles/tokens.css`. Не создавать глобальный класс только из-за совпадения одного значения.
- Варианты классов по данным перечислять явной картой, когда это возможно: так их проверяет ESLint. Перед удалением CSS проверять также динамические обращения и состояния.
- CSS ленивой страницы подключать из её компонентов, чтобы не загружать его заранее через App.

## Шрифты и изображения

- Использовать локальный Inter и существующие токены шрифта. Поднаборы latin, latin-ext и cyrillic покрывают разные символы и не считаются дубликатами.
- Не добавлять отдельные файлы начертаний, если их покрывает variable font. Сохранять `font-display: swap` и проверять кириллицу и фактические запросы браузера.
- Для растровых иллюстраций использовать оптимизированный WebP/AVIF. SVG оставлять для векторной графики; не оборачивать base64 PNG в SVG.
- У изображений задавать размеры или aspect-ratio. Изображения ниже первого экрана загружать лениво; главный баннер не задерживать lazy-loading.
- Не подставлять одно изображение несколько раз ради фиктивной галереи.

## Компоненты

- Перед созданием нового компонента сначала проверить, нет ли уже похожего.
- Переиспользовать существующие компоненты, если они подходят.
- Не создавать дубли компонентов.
- Если одинаковая разметка повторяется 2+ раза — вынести в компонент.
- Не делать один огромный компонент.
- Повторяющиеся списки/карточки выносить в data-файлы.
- Не хардкодить большие массивы прямо в JSX.

- Для карточек товаров, цены, кнопок, хлебных крошек, пустых состояний, полей и статусов сначала проверять `src/components/ui`; для галереи и сводки товара — `src/components/product`.
- Модальные окна строить на общем `Modal`, чтобы не дублировать управление фокусом и блокировкой прокрутки.

## Данные и расчёты

- Товары главной, каталога, корзины и избранного брать из общего каталога. ID должны быть стабильными; не генерировать копии товаров для заполнения сетки.
- При изменении ID поддерживать старые ссылки и сохранения через `productAliases.js`. Нормализовать количество, объединять дубли и ограничивать его остатком.
- Цены хранить целыми копейками, расчёты выполнять численно, отображение — через `formatMoney`. Не извлекать сумму из строки с валютой.
- Промокоды, бонусы и доставку рассчитывать общей моделью. Условия в баннерах, карточках и корзине должны совпадать.
- Изменения скидок, порога доставки, остатков и миграции сохранений проверять тестами на границах значений.
- Содержимое localStorage считать внешними данными. Ошибки чтения, JSON и записи не должны ломать интерфейс.
- Не выдумывать состав, аллергены, калорийность, условия хранения, реальные контакты или доступность доставки.

## JSX / React

- Не использовать key={index}, если есть стабильный id.
- Не добавлять новые зависимости без разрешения.
- Не менять роутинг без задачи.
- Не придумывать новые страницы, если их не просили.
- Не оставлять href="#" или href="".
- Использовать <a> только для реальной навигации.
- Использовать <button> для действий.

- Демо-действия должны иметь понятный локальный результат и явное пояснение, что данные не отправляются. Не показывать успешную отправку, заказ или авторизацию, если реального действия нет.
- При ленивой загрузке страницы сохранять общую шапку и подвал; Suspense размещать внутри основного содержимого.

## Accessibility

- У кнопок должен быть понятный текст или aria-label.
- У изображений должен быть alt, если они не декоративные.
- Декоративные иконки делать aria-hidden="true".
- Модальные окна должны иметь role="dialog", aria-modal="true", aria-labelledby.
- Модалки должны закрываться по Esc и кнопке закрытия.
- Не убирать видимый focus state.

- Фокус при открытии модалки должен переходить внутрь, Tab/Shift+Tab — оставаться внутри, после закрытия — возвращаться к инициатору. Фон должен быть недоступен для взаимодействия.
- На странице должен быть один осмысленный h1; сохранять main, skip-link и доступную навигацию после смены маршрута.
- У полей должны быть связанные label, подсказки и ошибки через aria-describedby; результат действий объявлять через status/alert по назначению.
- Проверять действия с клавиатуры. Соблюдать prefers-reduced-motion и сохранять читаемый контраст текста.
- Изменения общей вёрстки проверять на 320, 390, 768 и 1280 px, а также с увеличением текста до 200%; не маскировать переполнение через overflow-x: hidden у body.

## Workflow

Перед началом реализации:

1. Прочитать AGENTS.md.
2. Изучить только релевантные файлы.
3. Коротко написать план.
4. Потом делать минимальные изменения.

После реализации:

1. Запустить npm run lint.
2. Запустить npm test при изменении данных или логики.
3. Запустить npm run build.
4. Проверить git diff --check и затронутые сценарии в браузере.
5. Обновить PROJECT_NOTES.md, если изменились принятые решения или ограничения.
6. В ответе написать:
   - какие файлы изменены;
   - что сделано;
   - какие проверки запускались;
   - остались ли риски.

После создания AGENTS.md ничего больше не меняй.
